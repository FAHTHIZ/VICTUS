# Subsystem maturity and known limitations

Assessed 2026-11-18 by reading the code and running the full test suite (Slices 1-78). The labels are deliberately conservative:

- **Production-ready**: no subsystem has this label yet. It requires a shipped or externally used game, validation on real hardware for every supported platform, and stable public APIs. None of these exist yet.
- **Usable**: implemented end to end (runtime, serialization, editor UI where relevant, scripting access), covered by automated tests, and used by a template or sample game. Expect API changes.
- **Experimental**: works and is tested, but has narrow coverage, unmeasured performance, or lacks the editor or workflow support needed for real projects.
- **Incomplete**: part of the system exists; important parts that games need are missing.
- **Missing**: not implemented.

Evidence for every item is in [STATUS.md](STATUS.md); platform coverage is in [PLATFORM_SUPPORT.md](PLATFORM_SUPPORT.md).

## Cross-cutting limitations

- **Hardware:** every rendering result was produced on Mesa lavapipe (software Vulkan) or CI's virtualised Apple GPU. Frame-time numbers in STATUS.md are for that setup and do not predict real GPU performance.
- **Determinism:** capture/replay is verified on one compiler and machine; cross-platform floating-point determinism is not.
- **Device loss:** SDL_GPU 3.4 has no device-lost signal. VICTUS infers loss from repeated failed GPU operations and exits cleanly (exit code 3; the editor autosaves first), but cannot recover and keep running. Only injected failures have been tested, not a real driver reset or GPU removal.
- **Starter characters:** the Vanguard robots (docs/CHARACTERS.md) are rigidly skinned (one joint per vertex, no soft deformation); their lower LODs are meshoptimizer simplifications, not authored; sockets are named child nodes rather than a socket component; the template scales them to a 1.45 m player to fit the existing capsule; regenerating them from source needs Blender's `bpy` wheel and is not bit-reproducible.
- **Static analysis:** clang-tidy runs on engine, editor, tools and apps sources (see CONTRIBUTING.md), and CI fails if any tracked source of those trees is not analysed; test sources are not linted, and the job is not yet a required status check (owner-only branch-protection setting).
- **Third-party advisories:** cgltf 1.15 has four open advisories with no upstream fix. VICTUS validates accessors and unpacks sparse data itself before handing glTF data to cgltf (see THIRD_PARTY_AND_LICENSES.md); untrusted glTF files should still be treated with care.
- **Crash reports:** the handler runs inside the crashing process (ADR-0072), so heap corruption or a destroyed stack can prevent a report; there are no minidumps, no crash upload or aggregation. Linux reports are verified end to end; Windows (unhandled-exception filter) and macOS handlers are compiled in CI but not run against a real crash, Windows frames have no build-id (symbolize them with the matching .pdb), and Android reports have no stack frames. The editor does not yet start a crash session or offer "Create diagnostics bundle" (library function ready: `player::create_diagnostics_bundle`).
- **Studio samples page:** the editor finds sample projects in the source tree it was built from or in `VICTUS_SAMPLES_DIR`; installed or moved builds show an empty Samples page until that variable is set.
- **Studio guidance:** Help topics and the Getting Started checklist are built into the editor in English only; checklist progress and the interface size are per user, not per project; the size presets are fixed steps (90 % to 175 %, or any value with `--ui-scale`) and do not follow the operating system's display scaling.
- **Studio panels:** which panels are open and the chosen layout preset are not saved between sessions; dock positions are (editor_layout.ini).
- Acoustics (ADR-0096): occlusion models transmission through surfaces only — no diffraction around edges, no reflections, propagation or portals; each surface counts once regardless of thickness; the colour of an occluded voice is a single first-order low-pass (2.5 kHz/400 Hz tilt), so the 15 kHz band is not matched separately; reverb zones and the underwater filter act on whole buses (one listener, no per-source room); occlusion needs a bound PhysicsWorld (static/dynamic Jolt colliders), 2D physics does not occlude; no Studio preview of rays or zones yet; no HRTF.
- Water (ADR-0095): volumes are axis-aligned boxes without a bottom (rotation is ignored); reflections show the environment/sky only (no planar reflections or SSR of scene objects); water receives no shadows and writes no TAA motion vectors, so fast waves can smear slightly with TAA; transparent objects under the surface draw over it; buoyancy samples one wave plane per body at its centre and uses Jolt's bounding-box volume for capsules and cylinders; 2D bodies and ragdoll bones do not float; the editor preview animates with wall-clock time; no FFT ocean spectrum yet.
- Gameplay framework (ADR-0094): runtime `Timers`, `Attributes` and `Inventory` state has no Studio inspector yet (edit `Tags`/`AttributeSet` and inspect at runtime via scripts); attributes, effects and inventories are not replicated over the network; there are no interactable/prompt components yet.
