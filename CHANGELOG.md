# Changelog

All notable changes to VICTUS are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html); before 1.0.0 a minor version may change public C++ APIs (see "Compatibility" in [docs/RELEASE_PROCESS.md](docs/RELEASE_PROCESS.md)). Project, scene and asset file formats carry their own version numbers and are migrated on load; any format change is listed under "Changed".

Every entry links to the evidence in [docs/STATUS.md](docs/STATUS.md); nothing here claims more than STATUS verifies. Platform and hardware limits are in [docs/KNOWN_LIMITATIONS.md](docs/KNOWN_LIMITATIONS.md).

## [Unreleased]

No VICTUS version has been released yet. The first tagged release will be 0.2.0 (the version in CMakeLists.txt) and will move this section under `## [0.2.0] - YYYY-MM-DD`.

### Added

- World-space triplanar materials and CC0 starter content (ADR-0197). `.vmat` `triplanar` / `triplanar_sharpness` project every texture from world position (`uv_scale` = repeats per metre), so textures tile evenly on scaled blocks with no stretching; Studio material panel Triplanar checkbox and Blend Sharpness slider. The 3D and No-Code 3D templates now ship five 1K CC0 PBR materials (grass, rock, planks, metal, paving) and a CC0 HDR sky used for the background and image-based lighting; the No-Code 3D level's scenery uses them instead of flat colours. ([evidence](docs/STATUS.md#2026-11-22--world-space-triplanar-materials-and-cc0-starter-content-adr-0197))
- Screen-space reflections on water (ADR-0196). Water mirrors the objects around it on Medium, High and Ultra (16 / 32 / 48 ray steps), fading to the environment reflection off screen and at the screen edges. `RenderSettings::screen_space_reflections`, `ssr_steps`, `ssr_max_distance`, `ssr_thickness`; the render path report lists `ssr`. ([evidence](docs/STATUS.md#2026-11-22--screen-space-reflections-on-water-adr-0196))
- Spot light cookies (ADR-0195). `LightComponent` field `cookie` projects a texture asset through a spot light's cone (window frames, leaf shadows, stained glass), shaping its light on surfaces, its light shafts in volumetric fog and its baked light in lightmaps. `SceneRenderer::set_cookie` keeps up to 64 cookies in a storage-buffer atlas; Studio Inspector Cookie field; `victus check` reports missing cookies and cookies on other light types. ([evidence](docs/STATUS.md#2026-11-22--spot-light-cookies-adr-0195))
- Rectangle area lights, bulb radius and Baked lights (ADR-0194). `LightComponent` type `area` with `width`/`height` lights one side of a rectangle (windows, screens, softboxes) with exact diffuse irradiance and representative-point glossy highlights; point lights gain `radius` for wider, softer highlights; `baked` moves a point, spot or area light's direct light and soft shadows into the lightmap and probes. Studio: Add > Area Light, Inspector fields and a viewport outline. ([evidence](docs/STATUS.md#2026-11-22--rectangle-area-lights-bulb-radius-and-baked-lights-adr-0194))
- Studio UI Editor (ADR-0193). A canvas window draws the edited game UI with the player's own renderer at a chosen preview size (reference, desktop, phone and tablet); click to pick, drag to move, eight handles to resize, grid snap (Alt to override), arrow-key nudges and an anchor picker that never moves the element. Each gesture is one undo step; Add creates any of the twelve element kinds. Single selection only. ([evidence](docs/STATUS.md#2026-11-22--studio-visual-ui-editor-canvas-adr-0193))
- Native plugins in the Studio (ADR-0192, plugin API 1.1). Editor-target plugins load with the project and can register commands through `victus.editor.1` (`add_command`, `notify`); each command that changes the scene is one undo step. Play swaps in the player-target plugins and Stop restores the editor ones. The Plugins panel lists every manifest with its state, Enabled toggle, Run buttons and New Plugin; commands also appear in a Plugins menu and the command palette. ([evidence](docs/STATUS.md#2026-11-22--native-plugins-in-the-studio-with-editor-commands-adr-0192))
- Behaviour Tree Editor: drag a node onto another to make it the last child, or onto its edge to place it before or after; refused drops show the reason (ADR-0191). ([evidence](docs/STATUS.md#2026-11-22--drag-and-drop-reparenting-in-the-behaviour-tree-editor-adr-0191))
- Sequencer curves (ADR-0190). Bezier keys with `auto` (monotone, no overshoot), `flat`, `user` and `broken` tangents; `property` tracks animate any reflected component field (plus Camera, Light, MeshRenderer and Sprite fields); the Studio's Curves view edits keys and handles with pan, zoom, double-click insert and undo. Existing sequence files are unchanged. ([evidence](docs/STATUS.md#2026-11-22--sequencer-bezier-tangents-property-tracks-and-curve-editor-adr-0190))
- Background import queue in the Studio (ADR-0189). Opening a project, Reimport All and dropped files import on worker threads; Assets > Import Queue (or the status-bar "Importing n/m" button) shows per-file progress and errors with Pause, Cancel, Retry Failed and Clear Finished. ([evidence](docs/STATUS.md#2026-11-22--background-import-queue-in-the-studio-adr-0189))
- Low quality tier switches from 4x MSAA + FXAA to TAA with temporal upscaling when the render scale drops below 0.65 (`RenderSettings::taa_below_scale`, measured in docs/audits/LOW_TIER_AA.md; ADR-0188). `victus run --taa off` disables the switch. ([evidence](docs/STATUS.md#2026-11-22--low-tier-switches-to-taau-below-065-render-scale-adr-0188))
- Material `responsive` (0..1) marks blended meshes such as glass or holograms in the TAA reactive mask so they stop smearing; the Studio material panel gains Blend, Responsive and Coverage Response controls (ADR-0187). ([evidence](docs/STATUS.md#2026-11-22--per-material-responsive-flag-for-blended-meshes-adr-0187))
- Machine-wide shared cooked-asset cache (ADR-0180). Identical imports are hard-linked from `~/.cache/victus/cooked` (per-OS locations; `VICTUS_SHARED_CACHE` moves or disables it, `VICTUS_SHARED_CACHE_MB` caps it, default 8192). A second `victus new --template 3d` took 1.3 s instead of 24.4 s. Model metas gain `rgba8_max_size` to drop uncompressed copies of large texture levels. ([evidence](docs/STATUS.md#2026-11-21--human-starter-characters-adr-0179-and-shared-cooked-cache-adr-0180))
- Volumetric fog noise patches with wind drift and sun self-shadowing: `volumetric_noise`, `volumetric_noise_scale`, `volumetric_wind`, `volumetric_self_shadow` on the Environment (ADR-0186). ([evidence](docs/STATUS.md#2026-11-21--heterogeneous-volumetric-fog-and-self-shadowing-adr-0186))
- Modular equipment on both starter characters: boots, gloves, a belt and a backpack with shoulder straps. Each item is its own skinned node (`Orion_Boots`, `Orion_Gloves`, `Orion_Belt`, `Orion_Backpack`) that you can hide in Studio or with `entity:set_visible(false)`, and it carries baked PBR maps (leather, rubber tread, webbing, a metal buckle, ripstop). The build checks clearance against the body in the rest pose (ADR-0185). ([evidence](docs/STATUS.md#2026-11-21--starter-character-equipment-adr-0185))
- Dithered LOD cross-fade: level changes dissolve over `lod_fade_frames` (default 8) instead of popping (ADR-0184). ([evidence](docs/STATUS.md#2026-11-21--dithered-lod-cross-fade-adr-0184))
- Screen-space sun contact shadows: `contact_shadow_length` on the Environment adds sharp small-scale sun shadows, on in the 3D templates (ADR-0183). ([evidence](docs/STATUS.md#2026-11-21--sun-contact-shadows-adr-0183))
- docs/ENGINE_BENCHMARK.md compares VICTUS with IW 8.0, RAGE, id Tech 7, Unreal Engine 5, Frostbite and Decima and orders the remaining gaps. ([evidence](docs/STATUS.md#2026-11-21--sun-contact-shadows-adr-0183))

([evidence](docs/STATUS.md#2026-11-21--character-validation-socket-attachment-and-twist-drivers-adr-0181-adr-0182))

- Asset Trash in Studio (ADR-0177). Delete moves an asset to the project Trash; Assets > Trash... restores it with the same ID (references work again) or deletes it for good. With the Assets panel focused, F2 renames, Delete deletes and Shift+Alt+F finds references. ([evidence](docs/STATUS.md#2026-11-21--asset-trash-and-assets-shortcuts-adr-0177))
- Behaviour Tree Editor in Studio (ADR-0176). Double-click a `.vbt` (or Assets > New Behaviour Tree) to edit AI trees visually: a top-down tree with a node palette, right-click Add Child, Wrap In, Change To, Move Left/Right, Duplicate and Delete, plain-words node settings, blackboard defaults, red outlines and a "Will not run" pill for problems, undo/redo, and Save that reloads the tree in a running game. During Play the selected entity's active path and node statuses show on the canvas. Engine: `ai::tree_to_json` writes trees back to `.vbt`. ([STATUS](docs/STATUS.md#2026-11-21--behaviour-tree-editor-adr-0176))
- Asset references in Studio (ADR-0175). Right-click any asset for Find References (Used by / Uses, by ID or by name), Rename or Move... (keeps the asset's ID, rewrites files that name it by path, saves and reloads the open scene), Delete... (shows what still uses it first), Copy Path and Copy ID. `assets::ReferenceIndex`, `rename_asset` and `delete_asset` back it. See [STATUS](docs/STATUS.md#2026-11-21--asset-references-rename-and-delete-adr-0175).
- Studio Asset Store window (ADR-0174). Assets > Asset Store... opens a tab next to the Viewport: sources with their licences, live search with a type filter, thumbnail previews, a licence card saying in plain words whether you may sell, change and ship the asset, resolution/format choice, one-click Add to Project with progress and cancel, then Place in Scene, Use on Selected Object or Show in Assets, plus an "In this project" list with removal. Sketchfab tokens are stored privately in the user data folder; Kenney ZIPs import from the window. See [STATUS](docs/STATUS.md#2026-11-21--studio-asset-store-window-adr-0174).
- Starter characters rebuilt as human pilots (ADR-0179, docs/CHARACTERS.md). Orion (1.77 m) and Nova (1.68 m) come from the CC0 MakeHuman base mesh through a new reusable pipeline in `tools/characters`: 60-joint VICTUS Humanoid skeleton (the original 21 joints first and unchanged, plus twist, three-per-finger, jaw and eye joints), 44 ARKit-named facial blend shapes, separate eyes, teeth, tongue, brows, lashes and hair, sixteen 2048 px PBR maps per character (albedo, normal, packed ORM with baked AO, emissive), 41 clips (the original seven unchanged plus strafes, sprint, starts, stops, turns, crouch, actions, grip poses and facial clips) and eight sockets. GLBs use `KHR_mesh_quantization` (now accepted by the importer) and embed into the engine with `.incbin`; templates import their textures as BC7/ASTC. Asset ids, UUIDs, node names and the locomotion controller are unchanged. The SDF mannequin generator is removed.
- Asset Store (ADR-0174, new `engine/library` module). Search Poly Haven, ambientCG, Smithsonian Open Access, Sketchfab (with your own token), BigSoundBank, the National Park Service sound gallery and Kenney, and install models, PBR materials, HDRIs and sounds into `assets/library/<provider>/<id>` with one command: `victus library search|install|import-zip|list|remove|credits`. Only licences that allow commercial use, modification and in-game redistribution are installable (CC0, CC BY, public domain); material sets become a `.vmat` with an ORM texture packed for the renderer, every install records `provenance.json` and `LICENSE.txt`, the project's `CREDITS.md` is regenerated and `victus export` ships it next to the game. See [STATUS](docs/STATUS.md#2026-11-21--asset-store-providers-and-installs-adr-0174).
- Assets: FBX and OBJ import (ADR-0173). `.fbx` (binary/ASCII 3000-7700) and `.obj` + `.mtl` are model assets, read with the vendored ufbx v0.23.1: axis/unit/pivot conversion, meshes per material, PBR and legacy materials, embedded or sandboxed external textures, skins (unweighted vertices stay on the mesh), blend shapes with animated weights, baked animation stacks, lights and cameras. Studio copies an `.obj`'s material library and textures with it. Models holding only lights or cameras are now valid. Details in [STATUS](docs/STATUS.md#2026-11-21--fbx-and-obj-import-through-ufbx-adr-0173-gap-30-slice-2).
- Assets: glTF lights and cameras (ADR-0172). `KHR_lights_punctual` sun, point and spot lights and perspective/orthographic cameras are imported into cooked models (format v10), become Light and Camera components when a model is placed (cameras never primary), and are written back by glTF export. `.meta` keys `light_intensity_scale` (default 1/683, Blender's watt values), `import_lights` and `import_cameras`. See [STATUS](docs/STATUS.md#2026-11-21--gltf-lights-and-cameras-adr-0172-gap-30-slice-1).
- Rendering: named parameters and textures in surface shaders (ADR-0171). `.vshader` files declare `uniform float|vec2|vec3|vec4 name : hint = default;` and `uniform sampler2D name : hint_default_black;` lines (Godot syntax: `source_color`, `hint_range`, `hint_default_white/black`, `hint_normal`) readable in `surface()` and `vertex()`; up to four of each (one texture on GLES). Materials store `shader_textures`; the Material Editor shows colour pickers, range sliders and texture slots by name. See [STATUS](docs/STATUS.md#2026-11-21--named-surface-shader-parameters-and-textures-adr-0171-gap-17-slice-2).
- Rendering: surface shaders can move vertices (ADR-0170). A `.vshader` may define `void vertex(VertexInput i, inout Vertex v)` (object position and normal after skinning, uv, colour, time, params, `shadow` flag) that runs in the main pass and in sun, local-light and rain shadow maps, so swaying plants and waves cast matching shadows; errors point at the user's line ([STATUS](docs/STATUS.md)).
- UI: sliders, toggles, text fields, progress bars and rich text (ADR-0169). `UiSlider`, `UiToggle`, `UiTextInput` and `UiProgressBar` work with mouse, touch, keyboard and gamepad focus; text fields edit UTF-8 text at a caret and submit on Enter; `UiText.rich` understands `<b>` and `<color=...>`. Scripts get `on_value_changed`, `on_submit`, `entity:ui_value()` and `set_ui_value()` ([STATUS](docs/STATUS.md)).
- Navigation: tiled navmeshes (ADR-0168). Levels above a million voxel columns (or any level with `NavMeshSurface.tile_size` set) build a Detour tile grid at full voxel detail, cooked on up to 8 threads; a change re-cooks only the tiles it overlaps and agents keep walking. A 200 m x 200 m level builds 36 tiles in 256 ms on 2 vCPU (single tile: 647 ms) and adding a crate rebuilds one tile in 19 ms instead of 688 ms. `NavStats` reports `tiles` and `tiles_rebuilt` ([STATUS](docs/STATUS.md)).
- Traffic: lane-graph traffic (ADR-0167, new `engine/traffic` module). Road networks (`.vroads` JSON or `grid_network`) build a lane graph with curved junction connectors and split-phase traffic lights; `TrafficAgent` cars follow it with the Intelligent Driver Model, queue at red lights, give way at merges and follow simulation LOD. Add a `TrafficNetwork` component to an entity (with a car model as its first child) for traffic without code. 2,000 agents updated in 0.42 ms per frame on a 2 vCPU Release build ([STATUS](docs/STATUS.md)).
- Physics: wheeled vehicles (ADR-0166). `Vehicle` on a dynamic body and `VehicleWheel` on its child wheels give suspension, steering, an engine, an automatic gearbox, limited-slip differentials and anti-roll bars on Jolt's vehicle constraint. Drive them with `PhysicsWorld::set_vehicle_input` or Luau `entity:set_vehicle_input()`, read `vehicle_state()`, or tick `player_input` for W/A/S/D and gamepad driving. Studio's Inspector has a "Drivable vehicle" card with Make Vehicle (`physics::make_vehicle`). Script API 1.1 ([STATUS](docs/STATUS.md)).
- Gameplay: ordered and rate-limited systems plus simulation LOD (ADR-0165). `add_system` takes `SystemOptions{after, before, interval, offset}`; cycles and unknown names are reported by `schedule_diagnostics()`. `SimulationLod`/`SimulationLodSource` put entities in four distance tiers that update every 1/2/4/8 frames with the summed delta; behaviour trees, animators, Rotator and Oscillator follow it. Assigning tiers for 20,000 agents took 0.37 ms per frame on a 2 vCPU Release build ([STATUS](docs/STATUS.md)).
- Rendering: terrain foliage draws from cached instance groups (`SceneRenderer::cached_instance_group`, per-cluster draw and shadow distances). On lavapipe, scene extraction for 25,872 foliage copies fell from 1.67 ms to 0.07 ms per frame and per-frame uploads from 5,394 to 4 instances; the draw-distance edge is now per cluster of 32 (ADR-0164).
- Rendering: retained instance groups. `SceneRenderer::create_instance_group` registers many static copies of one mesh once; each frame `submit_instance_group` culls and LOD-selects per cluster of 64 and uploads nothing. On lavapipe the renderer's CPU time for 16,384 cubes fell from 6.83 ms to 0.43 ms per frame (ADR-0162).
- Animation: foot placement and foot locking (ADR-0163). `FootPlacement` on a character root plants its feet on slopes, steps and uneven ground, lowers the hips for the lower foot, tilts the feet to the ground and keeps planted feet from sliding. Studio: "Feet on the ground" card in the Inspector (Add Foot Placement, Stop feet sliding, Remove), "Entity: Add Foot Placement" in the command search, and View > IK and Foot Placement to see the chains and ground probes.
- Animation: layer masks can be weighted per bone (`"mask_weights": { "Spine": 0.3, "Chest": 1 }`), so aim and upper-body layers spread over several joints, and `"sync": true` keeps a layer's looping cycle in step with the base layer (ADR-0160); IK chains take a `max_bend` joint limit so tails and spines no longer fold back on themselves (ADR-0161); Studio's Animation window shows every layer with its state, a weight slider and its mask (ADR-0159, [STATUS](docs/STATUS.md)).
- Physics: fallen ragdolls can get up. `begin_ragdoll_get_up` (Luau `entity:ragdoll_get_up()`, Studio "Get Up" in play) moves the character to where it lies, facing where a get-up animation starts, tells whether it lies on its back, and blends smoothly from the lying pose back to the animation (ADR-0158). Script API 1.1 ([STATUS](docs/STATUS.md)).
- Player: survives GPU device loss. The device, GPU context, cached assets and scene view are recreated on the same window while the scene, scripts, physics, audio and network session keep running (`--device-recoveries`, default 3; ADR-0157). Verified with injected failures only.
- Scripting: the per-call time budget counts the script thread's CPU time instead of wall time, so a machine under load or a blocking native call no longer kills a healthy script; runaway loops are still stopped within the budget (ADR-0156).
- Scripting: the Luau script API is versioned (1.0, ADR-0155). `victus.project` records `"script_api"`; engines refuse scripts written for an incompatible version and `victus check` reports it. The API is frozen in `engine/script/api/` and CI fails when a binding is added without a minor bump or removed without a major bump. `victus script-api` prints, freezes and checks it; see docs/SCRIPT_API.md ([STATUS](docs/STATUS.md)).
- Export: game packs are zstd-compressed per file by default (when this landed the 3D template pack dropped from 6.5 MB to 2.4 MB; with the Orion and Nova characters it is 73 MB with `--target all` and 43 MB with `--target desktop`) and can be signed with an Ed25519 key (`victus pack keygen`, `victus export --sign-key`); the exported player then refuses a pack not signed by that key. `victus pack verify|list` check and inspect packs. Pack format version 2 (ADR-0154); version 1 packs still open ([STATUS](docs/STATUS.md)).
- Rendering: the Low tier renders the opaque pass with 4x MSAA when TAA is off, and alpha-tested foliage uses alpha to coverage, so edges and grass cards flicker much less on phones (`RenderSettings::msaa_samples`, `alpha_to_coverage`, `victus run --msaa`) (ADR-0152).
- Rendering: tree canopies made of leaf cards get LODs (fewer, larger cards at distance), and Low draws foliage one level coarser (`foliage_lod_bias`). The showcase forest at Low draws about half the triangles. Model importer version 7 (ADR-0151).
- Android: the activity keeps the manifest orientation (landscape by default) instead of SDL's rotation-lock rule. Rendering: Low/Medium shorten foliage range and drop far-foliage shadows (`foliage_distance_scale`, `foliage_shadow_fraction`); visibility CPU time down about 60 % on a 7k-draw scene; per-stage `render.cpu.*` profiler zones (ADR-0150).
- Export: `victus export --target android|desktop|all`. Android packs ship textures as ASTC only, at up to 1024 px, and are typically 5-8x smaller. A device that cannot sample ASTC decodes the levels on the CPU. Cooked format v9. `victus.nativeBuildType` Gradle property for debug APKs (ADR-0149).
- Rendering: a TAA reactive mask. Particles, ribbons, water and rain tell the TAA and temporal upscaling resolves to trust the current frame where they are drawn, so they smear and trail less; `RenderSettings::reactive_mask` / `reactive_max`, `victus run --reactive on|off`, `reactive_mask` in the render path report. See docs/STATUS.md (2026-11-20, TAA reactive mask, ADR-0143).
- Navigation: large navmeshes (2M+ voxel columns) build on a worker thread instead of stalling the frame; `NavigationSystem::ensure_built_async`, `building()`. Script time budgets no longer count navmesh builds or first-use model loads; `VICTUS_SCRIPT_SLOW_CALLS=<ms>` logs slow native script calls. See docs/STATUS.md (2026-11-20, background navmesh builds).
- Engine core: results and errors, logging, JSON with limits, sandboxed filesystem helpers, job system, profiler with Chrome/Perfetto traces, math, `.vpak` archives.
- Crash reports, session logs and unclean-exit detection for `victus` and `victus_player`; `victus diagnose` diagnostics bundles with path redaction and opt-outs; offline symbolizer (`tools/crash/symbolize.py`). ADR-0072, docs/DIAGNOSTICS.md.
- Rendering on SDL_GPU (Vulkan verified, Metal and D3D12 compiled): render graph, 2D sprite batching and 2D lights, forward HDR PBR with cascaded shadows, SSAO, bloom, auto exposure, TAA, decals, terrain, particles, quality tiers, spatial upscaling and debug views.
- ECS, scenes with prefabs and UUID identity, asset database with importers (glTF, images, audio), materials and surface shaders.
- Gameplay framework, Luau scripting with sandboxing and hot reload, visual scripting, Jolt 3D and Box2D 2D physics, Recast/Detour navigation, behaviour-tree AI, animation (skinning, controllers, sprite animation), timeline sequencer, in-game UI, localization, audio, save games, tilemaps.
- Multiplayer: client/server sessions over ENet with encryption by default, listen servers, dedicated `victus serve`.
- VICTUS Studio editor: start screen (new project with live validation, recent, samples, learn), docked workspace with a Window menu and five layout presets, viewport gizmos, inspector, asset browser, play mode, Problems panel with background project checks, File > Export Game, Help > Report a Problem (diagnostics bundle), crash notice after an unexpected exit, Help > About, a Hierarchy with search, a grouped Add menu and collapsed deep trees, an Inspector with a searchable Add Component picker and readable field names, a Console with severity filters, search, merged repeats and copy, an Assets panel with search, a type filter and a folder list, and importing files by dropping them on the window or with Import.
- Studio lessons: a first 2D platformer and a first 3D adventure built in seven steps from the Getting Started panel (or `victus_editor --lesson 2d|3d`); each step completes when the Studio sees it done and can be done for you.

### Changed

- Faster first frame for animated models. The animation system now reads only the skeleton, clips and morph names from a cooked model, skipping texture and mesh data, and loose cooked files are memory-mapped (`fs::map_file`). The model and texture loaders no longer copy the whole file before decoding, and collision meshes skip textures. Measured on the 3D template (Release, 2 vCPU, lavapipe): the first frame's `system.animation.update` dropped from 455-597 ms to 71-81 ms, and a two-frame `victus run` from 3.1-3.3 s to 2.5-2.8 s. Peak memory is unchanged at about 840 MB.
- Asset up-to-date checks cache each source file's hash per path, size and modification time instead of re-reading it on every load. Files modified in the last 3 seconds are always re-hashed. With this, the 3D template's first-frame animation update is 9.3-9.6 ms (it was 71-81 ms after the decode change above), and a two-frame `victus run` takes 2.35-2.44 s.
- The renderer decodes only the compressed texture variant this GPU will upload (`assets::VariantFilter`), keeping the first variant the device samples and skipping the rest without copying. A desktop no longer holds the ASTC copy of a character's textures, and a phone no longer holds a BC7 copy. Textures the device cannot sample keep every variant for CPU decode. On the 3D template, decoding one starter character now takes 41-53 ms instead of 124-191 ms (75 MB of the 150 MB of compressed texture data is skipped). The rendered frame is pixel-identical.
- Exported games read each model's skeleton and clips from a small `.vskel` pack entry written by export (`assets::make_skeleton_sidecar`), instead of decompressing the whole cooked model for animation. On the 3D template's Android pack, the first-frame animation update takes 8.6-8.9 ms instead of 150-168 ms, and each starter character is decompressed once at startup instead of twice; the pack grows by 0.3 MB. Packs exported before this change still load (the full model is read). Pack reads have `pack.read`, `pack.verify` and `pack.decompress` profile zones.
- glTF animation clips are keyframe-reduced on import (`animation::reduce_keyframes`, model import settings `keyframe_reduction`, `keyframe_rotation_error` in degrees, default 0.05, and relative `keyframe_error`, default 0.001). Linear keys that interpolation reproduces within those errors are dropped; first and last keys stay. The starter characters' skeleton and clip data goes from 1.8 MB to 0.4 MB each. The model importer version is now 9, so models re-import once.
- Starter character suits: the chest outline is now a tape instead of emissive piping, and the emissive strength drops from 4 to 2 (ADR-0185). Character GLBs grow to about 20 MB and about 205k LOD 0 triangles with equipment. Existing mesh, material and entity indices are unchanged. ([evidence](docs/STATUS.md#2026-11-21--starter-character-equipment-adr-0185))

### Fixed

- Studio: shortcuts pressed in the Behaviour Tree Editor (Ctrl+S, Ctrl+Z/Y, Delete) also acted on the scene; F2 and Delete in the Assets panel opened Help and deleted the selected entity. ([evidence](docs/STATUS.md#2026-11-21--asset-trash-and-assets-shortcuts-adr-0177))
- `victus run --quality <unknown tier>` now reports the error before creating a window or GPU device; on lavapipe the late exit could crash in the driver instead. ([STATUS](docs/STATUS.md#2026-11-21--behaviour-tree-editor-adr-0176))
- Physics: a ragdoll getting up could end with a bone (head, hips, an arm) still bent the way it lay instead of back in the animated pose. The check for "was this bone re-animated since the ragdoll wrote it?" compared quaternions with a threshold tighter than float rounding, so an unchanged lying pose was sometimes taken as the new animation target. The comparison is now exact; regression pushes added to the get-up test.
- Build: `-DVICTUS_WITH_GRAPHICS=OFF` configures and builds the headless core again. `engine/project` and the platform, project and animation tests and the animation benchmark depend on graphics-only modules, so they are now built only with graphics on. Verified locally: the headless build passes 19 of 19 test suites.
